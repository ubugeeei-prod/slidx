# lint 規則

リンタは、slidx が会場をモデルする部分です。スタイルチェッカではありません。ここの規則は
どれも、机ではなくステージで起きる何かのためにあります。

同じ規則集合に対して三つの場所で走ります。`vite build` の中、`slidx lint`、そして
エディタと言語サーバのライブです。書いてるときに見る所見が、ビルドを止める所見です。

## グループ

リンタが報告する順で、執筆のどこで直すのが一番安いかの順です。内容の形が先、それから
可読性、それから発表当日の心配。

## 所見の重さ

| 重さ      | 意味                                                               |
| --------- | ------------------------------------------------------------------ |
| `error`   | 止める。`vite build` を止め、`slidx lint` を非ゼロで終えます。     |
| `warning` | デッキは描画されますが、たぶん意図したようではありません。         |
| `info`    | 知っておく価値があり、無視して安全です。                           |

止めるのは `error` だけです。`--strict` は助言の所見を `slidx lint` の実行に足し、
プラグインの `failOnDiagnostics: false` は止める所見があってもビルドを終わらせます。
[前夜](tonight.md#the-build-will-not-finish) が、それが存在する状況です。

## unchecked はきれいではない

一つの規則が、三番目の答えを報告します。`overflow-clipped` は内容が実際に収まるかを測り、
それは改行位置に依り、ビルド時のモデルはそれを知るフォントメトリクスを持たないので、
ビルドがすでに起動するブラウザで測り、無いときは **unchecked** と報告します。

unchecked ときれいは反対の答えで、デッキが大丈夫なのは片方だけです。ブラウザを入れて、
規則が話せるようにします。

```bash
vp exec playwright install chromium
```

溢れグループの残りは、宣言した数の算術です。セーフエリア、会場の字幕帯。どこでも走り、
ブラウザも推測もありません。

## 一つを抑える

```bash
slidx lint --allow structure/too-many-bullets   # 一つのコード
slidx lint --allow structure                     # グループ全体
```

グループ名はその下のすべてを抑え、境界はスラッシュです。セグメントの途中で止まる接頭辞は
何も抑えないので、`--allow struct` は静かに `structure` を切りません。

抑える前に、何と言ったかを読んでください。診断はどれもコード、位置、具体的な次の行動を
持ちます。手を打てない警告はノイズで、メッセージはその基準で書かれています。

## オフライン規則は同じようには調整できない

`offline/remote-asset` が、「ビルドしたデッキはネットワークを要しない」を願望ではなく
真にします。抑えることはできます。そうすると、出荷するデッキは会場の Wi-Fi から何かを
取るデッキです。机で意図して決める価値のある判断で、会場で発見する判断ではありません。
