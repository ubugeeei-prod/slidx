# フロントマター

デッキは `---` で区切られた Markdown ファイルで、各スライドは YAML ブロックで開けます。
このページの表はすべて
[`slidx_lsp::vocabulary`](../../../crates/slidx_lsp/src/vocabulary.rs)
から描画されます。言語サーバが補完に答えるために読むモジュールです。サイトとエディタが
同じ言葉を見せるのは、集合が一つだからです。

フロントマターは意図的に開いています。slidx が聞いたことのないキーは拒否せず残すので、
テーマやプラグインが読め、自分の道具のためにキーを書いた著者がパーサと戦わずに済みます。

## キーが意味を持つ場所

デッキの最初のブロックは二つの仕事をしています。デッキを設定し、最初のスライドも
設定します。それ以降のブロックは一枚だけを設定します。キーを一つの表にせず二つに
分ける理由です。後のブロックの `title:` は静かに何もしません。どちらがどれかを言う以外に、
それを見せる方法はありません。

## 閉じた集合の中身

いくつかのキーは、決まった値の一つを受け付けます。下の各リストは、コンパイラがすでに
照合している定義から導出されるので、ここにある値は slidx が受け付ける値です。

`layout:` もその一つで、[専用のページ](layout.md) があります。値は半分で、もう半分は
各ブロックがどの領域を選ぶかです。

### `theme:`

組み込みは四つ。それぞれライトとダークを持ちます。会場の照明は当日までたいてい不明です。
色はすべてトークンで、組み込みテーマはリンタ自身のコントラスト規則に縛られるので、
読めないものを出荷できません。

### `transition:`

トランジションを名指したスライドは自分で決めます。`none` と言ったときも含みます。
沈黙だけがデッキのを継ぎます。`transition: false` は `none` の綴りとして受け付けます。
YAML がそれを真偽値として読み、デッキ全体のトランジションを切るスライドが、何も言わなかった
スライドとして読まれることになるからです。`push-up` は `rise` の綴りとして受け付けます。
動く種類はすべて `prefers-reduced-motion` の下でクロスフェードへ落ち、ビュートランジションを
実装しないブラウザは即座に遷移します。

<!-- slidx-docs: transitions -->

## ほとんど入ったスライド

```md
---
title: Making Decks Fast
event: SlidxConf 2026
duration: 20m
theme: editorial
aspect: "16:9"
---

# Making Decks Fast

<!-- notes:
Open with the outcome, not the agenda.
-->
```

ノートは `notes:` で始まる HTML コメントに住み、描画されたスライドの外に、語っている
言葉と同じファイルに残ります。

## slidx が読まないキー

何も起きず、何も文句を言いません。設計の開いた半分です。何かすると思ったキーがしなかった
なら、パーサではなく上の表と綴りを照合してください。すべてのキーで `camelCase` と
`kebab-case` の両方を受け付けるので、`autoSteps` と `auto-steps` は同じキーで、途中の
誤字はそうではありません。
