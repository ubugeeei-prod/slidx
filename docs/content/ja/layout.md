# レイアウトと領域

スライドがレイアウトを選び、レイアウトが名前付きの領域を出します。ブロックは自分が属する
領域を言い、他は書かれた順で既定の領域に着きます。

```md
---
layout: aside
---

## How the pipeline fits together

{.side}
![The four stages, end to end](./pipeline.svg)
```

仕組みはこれだけです。フロントマターの一語と、ブロックの上の一行。

## なぜ矩形ではなく領域か

何かを動かす明白な方法は自由なキャンバスで、ファイルに置くのは四つの浮動小数です。
誰もレビューできず、アスペクト比が違うと意味が変わり、規則はそれらについて判断できません。
幅を実行時にしか知らない箱の中で文字が読めるかを、リンタは言えません。

領域は同じ身ぶりに名前を付けたものです。`{.side}` は diff の一語で、2009 年から改装されて
いないホールの 4:3 プロジェクタでも正しい意味を持ち、溢れの規則が測れるものです。幾何は
スライドではなくレイアウトに属するからです。

## レイアウト

下の領域名は、属性行に書くものです。

<!-- slidx-docs: layouts -->

レイアウトは一つの `grid-template-areas` で、領域の名前 _が_ そのグリッド領域なので、
幾何を記述するのは一つの文字列であり、食い違える二つではありません。スライドはすでに
サイズコンテナなので、中のグリッドは拡大縮小を無料で継ぎます。どのプロジェクタの大きさでも
各領域はスライドの取り分で、transform もスクリプトもありません。

## 属性行

行単独の属性グループは、下のブロックに付きます。

```md
{.side}
![The pipeline](./pipeline.svg)
```

すでに二度会った同じ文法です。`{#key .class prop=value}`。テキストのスパンのあとに
[マーク](steps.md#addressing-part-of-a-line) として、フェンスの言語のあとに
[スニペットを公開する](tonight.md#somebody-is-going-to-ask-for-the-code) ために、
そしてここでは行単独で現れます。文法は一つ、一度だけ書いてあります。第二のパーサは
`prop="two words"` が何かについての第二の答えになるからです。

`{` で始まりグループとしてパースできない行は普通の本文で、何も言われません。波括弧で
始まる段落を書いている人は、間違えてはいません。

## レイアウトにない領域を名指す

ブロックは既定の領域に着き、ビルドがそれを報告します。両方大事です。トークの二十分前に
編集したデッキは描画されなければならず、静かに別の場所へ行ったブロックは、ステージから
見つける種類のものだからです。

所見はリンタではなくテーマから来ます。領域はレイアウトに属し、リンタはテーマについて
意図的に何も知りません。

## 溢れは領域ごとに測る

領域は自分の箱です。幅の三分の一の列は行の三分の一を持ち、スライド自身のスクロール高は
一列の下が落ちたことに気づきません。

なので各領域は別々に測られ、それぞれが領域を名指した所見を持ちます。「スライドが高すぎる」
は間違った半分へ送ります。ヘルプはスライドを割るのではなくブロックを動かせと言います。
溢れのグループが他に何を見るか、なぜ _unchecked_ が _きれい_ ではないかは
[lint 規則](lint.md) を見てください。

## ブロックを領域へドラッグする

  <img alt="段落をスライドの左列から右列へドラッグし、隣の Markdown に {.right} の行が増える" src="../../media/editor-arrange-light.png">
</picture>

キャンバスとファイルは一つの文書の二つのビューで、この録画が決着させる主張です。ゴーストは
カーソルではなく、ファイルがこれから言う領域と位置に吸い付くので、ドラッグ中にポインタの下に
見えるものが diff になります。ドロップは一つの操作なので undo は一回で、`{.right}` を
書きます。動かすブロックの上の一行です。

身ぶりにはキーもあります。グリップはボタンなので、タブ順はスライドのブロックを歩き、
矢印キーが一つ動かします。領域の中では上下、領域のあいだは左右。ポインタだけでしか
並べられないデッキは、書く人の半分が並べられないデッキです。

**既定** の領域へのドラッグはクラスを書くのではなく外します。レンダラにとって二つは同じことで、
diff の行になるのは片方だけだからです。領域から出して戻すドラッグは、何もコストしません。

`vp run record:editor` は、実 dev サーバに対してドラッグを演じることで録画を再生成します。
動かなくなった身ぶりは再現に失敗するので、もう起きないことの写真が残りません。
