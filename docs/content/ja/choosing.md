# トークに slidx を選ぶ

数週間後に枠があり、何で書くかを決めているところです。このページは主張と留保を
その順で書き、後半を隠しません。

読むより見たいなら、[ウォークスルー](start.md) が二十分でビルドしたデッキまで
連れていきます。[はじめる](index.md) が、それが何であるかの一ページです。

## 何のためか

スライドを作るのは、トークの短い部分です。slidx は長い部分の周りに組まれています。
一週間前、会場、ステージの二十分、そして発表のあとになかなか起きない公開。

| いつ         | slidx がすること                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 書いてるとき | Markdown と、同じファイルを書くビジュアルエディタ。編集はバイト範囲の splice なので、diff はレビューできます。                |
| 書いてるとき | 言語サーバ。入力中の診断、フロントマターとステッププリセットの補完、デッキのアウトライン。                                    |
| 出発前       | 会場をモデルするリンタ。プロジェクタの白飛び、最後列からの可読性、実ブラウザで測った溢れ、枠に対する時間。                    |
| 当日朝       | `slidx doctor`。電源、ディスク、時計のずれ、テーマが名指すフォント、画面を録っているもの、ネットワークが本当に動くか。        |
| ステージ上   | 時計が一番大きいプレゼンタービュー。スライドごとの予算に対する遅れ／余裕、落とすべき任意スライドの名前。                      |
| ステージ上   | 宣言したデモのフォールバック。ライブと、動いている録画が両方マークアップにあり、一つのキーで切り替わります。                  |
| ステージ上   | 共有したコードフェンスが、デッキ自身の出力の中の独立したページになり、スライド上の QR がそれを指します。                      |
| あとで       | `slidx publish` は、提案時点で書いたフロントマターから行き先を計画し、アカウントが要らないことだけを実行します。              |
| 何か月後     | このマシンが見たデッキに対する `slidx list`、`grep`、`cd`、`open`。トークがどのリポジトリにあったかは、覚えていないからです。 |

長い版は [README](../../../README.md) に、正直な版は [ROADMAP.md](../../../ROADMAP.md)
にあります。チェックされていない行は、なぜ終わっていないかを言い、チェックされた箱が
何を意味してよいかを最初に定義しています。

## 何に署名しているか

これは設定ではなく性質です。一つでもトークに合わなければ、下まで合わず、設定では動きません。

**ソースはリポジトリの Markdown です。** バイナリのデッキ形式も、ホストされたエディタも
ありません。ビジュアルエディタは自分のマシンで動き、開いているファイルに書きます。

**出力はアプリケーションではなくページです。** スライドごとに一つの HTML 文書。
ナビゲーションはブラウザがリンクを辿ることなので、スライドは共有・ブックマーク・索引・
印刷ができ、スクリプトが走る前に描画されます。

**リモートアセットはビルドエラーです。** フォント、画像、スタイル、スクリプトは
インラインかバンドルです。CDN に手を伸ばすデッキはビルドしません。これがプロジェクトで
いちばん意見の強いところで、調整できません。防ぐ失敗は、直せない会場で起きるからです。

**ビルドは Vite です。** `@slidxjs/vite-plugin` が設定の全部で、意図的に
`slidx build` はありません。パイプラインは一つです。`slidx` バイナリは別で任意であり、
ビルドができないことをします。

**あなたとして公開しません。** `slidx publish` の下に HTTP クライアントもトークン
ストアもありません。ペイロードを組み立て、ディスクに置くべきものを書き、残りを貼る
ページを名指します。欠けではなく性質です。あなたとして投稿できるツールは、認証情報を
預けるツールです。

## いま実際にどこか

**プレアルファで、未リリースです。** npm にも crates.io にもありません。タグ付き
リリースも公開バイナリもありません。動かすにはリポジトリをクローンします。
[ウォークスルー](start.md) がその手順です。

README が出荷済みと書いたものは、作られ、テストされ、人が到達できます。最後の句が
本当に仕事をしていて、[ROADMAP.md](../../../ROADMAP.md#what-a-checked-box-means-here)
がその理由を説明しています。終わっていない部分は、願いではなく形の決まった Issue
です。

仮定ではなく検証されていること。デッキは Chromium、Firefox、WebKit で描画されます。
パイプラインは Node、Bun、Deno と macOS、Linux、Windows で動きます。それぞれが
主張ではなく CI のジョブです。

## 別のものを使う理由

**今日インストールする必要がある。** レジストリパッケージがありません。クローンから
ビルドできないなら、三週間後のトークには使えません。

**ローカルのツールチェーンを回せない。** slidx はビルドです。自分のマシンか CI。
ホストされているものはありません。

**デッキが一つのスクロール文書でなければならない。** slidx はスライドごとに一ページへ
コンパイルし、設計全体がそれに寄りかかっています。

**スライドがデザインツールの出力である。** slidx は Markdown をテーマで描画します。
自由な配置は用途ではなく、本当に絵の集まりであるデッキはずっと戦うことになります。

## 三週間前、具体的に

**今日、二十分。** [ウォークスルー](start.md) を一通りやる。書き方に合うかは、終わりに
分かります。

**書いているあいだ。** `vite dev` を動かし続ける。リンタはビルドの中にあるので、
ノート PC では見えないことが、まだ手を打てるうちに報告されます。前夜ではありません。

**一週間前。** 実際に話すマシンで `slidx doctor` を走らせる。書いたマシンと違うなら、
書いた方ではありません。プレゼンタービューを開いて一度リハーサルする。時計は
フロントマターが宣言した枠に対して動き、ペースはスライドごとの予算と比べます。
「時間オーバー」と「7 枚目に四分かけて予算は一分」は違います。

**前夜。** [前夜](tonight.md) は症状ごとの索引です。落ち着いているいま、ブックマークして
おいてください。
