# slidx コマンド

バイナリはビルドとは別で、任意です。三つのことをし、どれもデッキをビルドすることでは
ありません。**書く** — ターミナルを離れたくないとき。**会場** — どのエディタも見えない、
トークに起きようとしていること。**すでに持っているデッキ** — 年に四回話す人は四つの
リポジトリを持ち、どれがどこにあるか覚えていないからです。

録画は本物のバイナリを、執筆のライフサイクルに通します。デッキとエディタを始め、整形、
lint、export、会場を調べ、公開計画を用意します。`vp run media` が各コマンドの新しい出力を
撮ります。

このページのすべては
[バイナリ自身が読む表](../../../crates/slidx_cli/src/command/table.rs)
から来ます。引数パーサ、ヘルプ、六つのシェル補完スクリプトが同じ一つを読み、表と
ディスパッチャが食い違うと上流のテストが失敗します。なのでこのページは、パーサが受け付けない
フラグを記述できません。コマンドラインのリファレンスが普通に間違えるやり方です。

`-h` はどこでも受け付け、その理由で下の表からは外してあります。

## 入れる

公開バイナリはまだありません。初回リリースまでは。

```bash
cargo build --release -p slidx_cli
./target/release/slidx --help
```

[README](../../../README.md) が名指す二つの入れ方 — シェルスクリプトと npm ラッパ — は
同じ事前ビルド済みバイナリを渡し、どちらもまだ渡すものがありません。

## slidx が持たないコマンド

これらはどれも、打つ理由のあるものです。「unknown command」と答えると、できることを
できないと信じさせるので、拒みは代わりに打つものと、なぜかを言います。

<!-- slidx-docs: declined -->

意図的に `slidx build` はありません。それは `@slidxjs/vite-plugin` の仕事で、パイプラインが
一つであることが全部の要点です。確認するデッキが渡すデッキです。他に描けるものがないからです。

## シェルの助けが要る二つ

`slidx cd` はディレクトリを変えずにパスを印字し、それは直されるのを待っている制限では
ありません。**子プロセスは、自分を起動したシェルの作業ディレクトリを変えられません。**
なので解決し、シェル関数が入る。ディレクトリジャンパがどれも組まれる同じ対です。
`slidx shell` がその関数を、使っているシェル向けに書きます。
