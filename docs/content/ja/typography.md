# 組版

テーマが基準サイズと比を選び、スライド上のサイズはすべてそこから来ます。このページは、
サイズが決めない三つのこと — 行の間隔、字の詰まり、行が走ってよい長さ — と、英語で書いた
デッキが得ない、日本語で書いたデッキが得るものについてです。

どれもスライドでは設定しません。テーマがカスタムプロパティとして出すので、一つを上書きする
ブロックは、理由のある値を上書きしています。

## 二つの曲線

両方の量はサイズと一緒に、反対方向へ動きます。

**トラッキングは、活字が大きくなると閉じます。** サイドベアリングはグリフと一緒に拡がり、
二字の隙間に対する目の許容は拡がらないので、本文サイズに合うトラッキングのままディスプレイ
サイズに組むと緩く見えます。なのでトラッキングはテーマ自身の基準でゼロで、そこから動きます。
上は負、**下は正**。キャプションは本文よりトラッキングを欲し、一つの固定値では表せない半分です。

**行送りも、活字が大きくなると閉じます。** 同じ理由と、もう一つ。行送りは下の行に対して
決まり、見出しは短いからです。

両方はテーマの基準に錨を打つので、テーマは一つの行送りを述べて一貫した梯子を得ます。
尺度の違う二つのテーマは違う数字を得ます。それが要点です。

|               | `minimal` (32px, 1.25) | `editorial` (34px, 1.333) |
| ------------- | ---------------------- | ------------------------- |
| body leading  | 1.50                   | 1.60                      |
| `h1` leading  | 1.15                   | 1.15                      |
| `h1` tracking | −0.0147em              | −0.0190em                 |

`editorial` は散文のテーマなので本文をより開きます。`h1` はより _詰まります_。1.333 の比は
1.25 より見出しを基準から遠くし、曲線はその距離で閉じます。二つの `h1` 行送りが同じ数字に
着くのは、二つの効果が打ち消し合うからです。高い錨と、長い下り。

## 行長

行が長すぎるのは、次の行へ戻るときに目が場所を失うときです。読める範囲は慣例では文字数で
引用されます。ラテン散文で 45–75、ディスプレイ活字ではそれより少なく。slidx はそれを
`em` の一つの長さとして引用します。

|                           |        |
| ------------------------- | ------ |
| `--slidx-measure-prose`   | `30em` |
| `--slidx-measure-heading` | `13em` |

二つのスクリプトに一つの数です。二つの比が打ち消し合うからです。漢字やかなは 1em を占め、
ラテン小文字は平均しておよそ半分です。日本語は英語のおよそ二倍の文字数に組まれるので、
運ぶ量もおよそ二倍です。30em はラテン六十文字か日本語三十文字で、それは同じ文です。

`em` は要素自身のサイズに対して解決するので、一つの宣言が尺度のすべての段で正しい行長です。
以前は `22ch` でした。`0` の送り、ラテンの尺度で、日本語ではおよそ十二文字になり、見出しを
語の途中で折りました。

**上限であり、目標ではありません。** ブロックは内容に合うので、三語の行は三語の幅のままです。

## 日本語、中国語、韓国語

上のすべてはスクリプト中立です。四つはそうではなく、文書言語が `ja`、`zh`、`ko` のとき
デッキはそれらを得ます。

**行送りは 0.2 開きます。** ラテンの行の分離は、x-height の上とベースラインの下の余白が
一部を担い、そこで 1.5 が豊か見える理由です。CJK の行はそういう余白のない、埋まった em 箱の
並びなので、同じ比は目に見えて詰まります。本文は 1.7 に着き、日本語の実務が行送りに引用する
1.5–2.0 の中です。

**トラッキングはゼロで、代わりに `palt` が仕事をします。** 漢字はほとんどサイドベアリング
なしで em 箱を埋めるように描かれるので、ラテン書体が手放す余地のあるトラッキングは、画から
出てしまいます。`font-feature-settings: "palt"` は、フォントがすでに持つプロポーショナルな
送りを頼みます。見出しに。慣例が置く場所です。

**約物は詰めます。** 日本語の括弧や句点は、インクが片側に寄った 1em 箱の中に描かれるので、
`「約物」の` は引用の両側に穴を開けて組まれます。`text-spacing-trim` が組版の答えで、
なぜか言えずにすぐ気づく、ここにある唯一のものです。

**行は文節境界で折れます。** 日本語に空白はないので、既定は行が足りなくなったところで折れます。

```text
  before                          after
  ・行末の禁則処理が甘く、        ・行末の禁則処理が甘く、句読点が行頭に
    句読点が行頭に来てしまうことがあ    来てしまうことがある。
    る。
```

`word-break: auto-phrase` は見出しだけでなく散文にも付きます。選択です。普通の助言は
ディスプレイ活字に限れと言います。句境界は右端をより不揃いにするからです。スライドでは
どの行もディスプレイ活字です。三行、十五列目から読む、不揃いを壊す本文の列はありません。

`line-break: strict` も同じ理由で付きます。既定は行頭に小書きのかなや長音符を許し、
スライドはそれが見える場所です。

### どのブラウザがどれをするか

サポートサイトからの写しではなく、マトリクスがカバーする三つのエンジンで測っています。
`packages/vite-plugin/test/browser.test.ts` がそれぞれに聞き、ここの答えが間違っていたら
失敗します。ブラウザが _得た_ ときも含み、下の劣化は起きなくなった瞬間に記述されなくなります。

|                            | Chromium | Firefox | WebKit |
| -------------------------- | -------- | ------- | ------ |
| leading, tracking, measure | ✓        | ✓       | ✓      |
| `line-break: strict`       | ✓        | ✓       | ✓      |
| `palt`                     | ✓        | ✓       | ✓      |
| `text-spacing-trim`        | ✓        | —       | —      |
| `word-break: auto-phrase`  | ✓        | —       | —      |

最後の二つをどちらも得ないデッキは、ブラウザが独力で日本語を組むように組まれます。どの
スライドもそこから始まります。その上のものはそれでも適用されるので、壊れではなく劣化で、
文書を跨ぐトランジションと同じ取引です。

## デッキの言語

フロントマターの `lang:`。デッキが宣言したとき。

```md
---
lang: ja
---
```

何も宣言しないデッキは、以前 `lang="en"` として出されていました。英語で書いていない
すべてのデッキに対して間違っている、具体的で自信のある答えで、三つのものが信じていました。
スクリーンリーダは英語の声を選び、ブラウザはラテンの改行を適用し、上の組版はどれも
適用されませんでした。

なのでフロントマターが沈黙のときは、スライドを読むようになりました。かなは日本語を証明し、
ハングルは韓国語を証明します。どちらも他の言語では使いません。どちらもない漢字は中国語です。
日本語の散文はかなを避けられません。助詞と送りがなはかなです。存在ではなく文字の
**過半数** なので、日本語の句を一つ引用する英語のトークは英語のままです。

宣言した `lang:` は常に勝ち、検出がラテンのタグを返すことはありません。英語とドイツ語を
見分けるには別種の証拠が要り、`en` はすでに既定です。

## 値を上書きする

上の数はすべてカスタムプロパティなので、エディタがすでに書き込むタグ付きスタイルブロック
経由で、スライドは一つを変えられます。

```md
<style data-slidx>
:root {
  --slidx-measure-prose: 44em;
}
</style>

A slide whose prose wants a longer line than the theme gives it.
```

このモデルに属するのは `data-slidx` ブロック内の `--slidx-*` 宣言だけで、レンダラは
文書ではなくそのスライド自身の要素にスコープします。印刷シェルで正しい理由です。そこでは
すべてのスライドが一つのページを共有します。

どれにもフロントマターのキーは、意図的にありません。組版の決定が属する場所はテーマです。
自分の行送りを運ぶスライドは、テーマが変わった瞬間にデッキの残りと合わなくなるスライドです。
