# Write Markdown. Get a website.

slidx compiles a Markdown deck into ordinary static HTML — one URL per slide,
no client router, nothing to boot. The visual editor writes to **the same
file**. A built deck asks nothing of anywhere but itself.

<video src="../media/deck.webm" controls loop muted playsinline preload="metadata" width="960"></video>

A built deck, driven by the arrow key a presentation remote sends. Every picture
and recording on this site is regenerated by `node scripts/record.mjs` from a
real run, so one that stopped being true fails to reproduce rather than quietly
showing a product that no longer exists.

## Sixty seconds

slidx is **not on npm or crates.io yet**. `vp add -D @slidxjs/vite-plugin`
installs nothing today. The configuration that will be, when it is, is the
whole of it:

```bash
vp add -D @slidxjs/vite-plugin
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { slidx } from "@slidxjs/vite-plugin";

export default defineConfig({ plugins: [slidx()] });
```

```bash
vp dev     # the deck, plus the visual editor at /__slidx/
vp build   # one HTML document per slide
```

Write `slides/0001.md` and it is on screen.

Until the first release, that install is a sentence about the future.
[From a clone to a built deck](start.md) is the path that actually runs — the
same commands this repository's own CI runs.
